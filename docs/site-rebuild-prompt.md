# Reusable site rebuild prompt

Use the following prompt with this repository open:

---

Rebuild the GitHub Pages site in site/ for VT / NerdFonts. Read the repository instructions, README.md, DESIGN.md, existing site code, and relevant skills first. Preserve unrelated working-tree changes. Produce a concrete, reviewable static HTML/CSS/JavaScript draft and explain what you removed, changed, and added.

Use the reviewed skills with distinct responsibilities:

- avoid-ai-design: lead the audit and implementation; identify source-backed findings and separate visual inference. Apply its second-order-default checks as well as ordinary anti-slop checks. Scope an optional detector to explicit site files and treat heuristic findings as advice.
- design-taste-frontend: infer audience and purpose; use selective typography, hierarchy, and redesign guidance. Override mandatory generated images, framework assumptions, motion defaults, and layout quotas with the project brief.
- antislop plus antislop-ui, antislop-human, and antislop-layoutmobile: use only relevant content, control, keyboard, contrast, and responsive rules. antislop-copywriting may guide labels. antislop-code applies only if comments need editing. Skip installation wizards, mode questions, duplicated audits, and lengthy delivery reports because implementation is authorized here.
- humanizer: perform one concise final prose edit in file/embedded mode, preserving technical claims, qualifications, font names, codepoints, licenses, links, commands, and code. humanize-writing is an alternative if unavailable; do not stack their full editing pipelines.
- Impeccable is a reviewed optional alternative for a future authorized tooling session; do not download or execute its engine or install hooks for this task. harshaneel/humanize and anti-ai-slop-writing are reviewed alternatives; do not activate their statistical sentence constraints, broad banned words, or detector-oriented loops.

Design this as a useful font workbench. Remove the slogan-heavy hero, glitter/sparkle branding, repetitive uppercase labels, decorative numbers, fake browser chrome, metric strip, redundant cards, decorative arrows, and duplicate closing pitch. Keep real setup steps, repository/release links, the official icon finder, width guidance, source-font comparison captures, and licensing qualifications.

Use Georgia titles, system-sans instructions, and monospace commands/specimens. Build a compact shared navigation, practical intro, source-grounded patch instructions, semantic NF/NFM/NFP table, and real comparison images. Do not imply this wrapper builds Propo or updates source font versions. Make the actual tradeoffs clear.

Implement a button cycling light, dark, and fun. Persist its choice across both pages and reloads. Light/dark use the DESIGN.md blue palette and flat restrained layout. Fun deliberately resembles a tacky 1990s GeoCities homepage: clashing yellow/cyan/magenta, Comic Sans/Times/Courier-like typography, grainy low-resolution graphics, a slow looping image around two frames per second, marquee text, and default-style beveled table borders. This user-requested theme is exempt from aesthetic bans. Keep text readable, controls operable, and layouts responsive. Provide pause/play for all decorative motion, including the animated image, and respect reduced-motion preference. No autoplay sound or rapid flashing.

Move root validation.html into site/validation.html. Add a prominent “Validate fonts” link styled as a button in the main navigation. Use the same shared header, footer, CSS tokens, theme controls, and retro controls in the tool. Preserve multi-file local loading, glyph groups, box art, width measurements, size selection, per-font removal, and clear-all. Files must remain local. Loaded-font specimens must not inherit the UI font. Explain that browser fallback and advances are not an exact cmap audit or terminal-width guarantee. Fix defects encountered in these existing paths.

Update the Pages workflow to publish site/ directly without copying a root validator, and update relevant documentation paths. Use plain CSS/JavaScript unless a dependency serves a demonstrated need; this brief does not require GSAP or generated imagery.

Inspect desktop/mobile layouts and behavior proportionally to the change, including all three modes, persistence, keyboard focus, animation pause, font loading/removal, and invalid files. Report only checks actually performed. Deliver the draft, the design decisions, and verification limits. Do not publish, commit, or modify global skill instructions as part of this task.
